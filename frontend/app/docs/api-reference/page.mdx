# API reference

Base URL: `http://localhost:8080` in development. All requests that set or
rely on auth cookies must be made with credentials included
(`fetch(url, { credentials: "include" })`), and the backend's
`FRONTEND_ORIGIN` must match the calling origin for CORS to allow it.

All responses are JSON. Errors take the shape `{ "error": "message" }`.

## `POST /api/auth/signup`

Creates an account and emails a 6-digit OTP. The account can't log in until
verified.

**Body**

| Field | Type | Rules |
| --- | --- | --- |
| `email` | string | required, valid email |
| `password` | string | required, min 8 characters |
| `companyName` | string | required, 1–200 characters |

**Responses**

| Status | Meaning |
| --- | --- |
| `201` | Created — `{ message, user }` |
| `400` | Validation error |
| `409` | Email already registered |

## `POST /api/auth/verify-otp`

Confirms the emailed code and activates the account. On success, sets the
access + refresh cookies.

**Body:** `{ email, code }` — `code` must be exactly 6 digits.

| Status | Meaning |
| --- | --- |
| `200` | Verified — `{ user }`, cookies set |
| `400` | Invalid or expired code |
| `404` | User not found |
| `429` | Too many attempts (max 5) — request a new code |

## `POST /api/auth/resend-otp`

Issues a new OTP, invalidating the previous one. Rate-limited to one
request per 60 seconds per account.

**Body:** `{ email }`

| Status | Meaning |
| --- | --- |
| `200` | New code sent (also returned for unknown emails, to avoid leaking which addresses are registered) |
| `429` | Cooldown active — wait before retrying |

## `POST /api/auth/login`

**Body:** `{ email, password }`

| Status | Meaning |
| --- | --- |
| `200` | Signed in — `{ user }`, cookies set |
| `401` | Invalid email or password |
| `403` | Email not verified yet (`code: "EMAIL_NOT_VERIFIED"`) |

## `POST /api/auth/refresh`

Reads the refresh cookie, rotates it (revokes the old one, issues a new
pair). No body required.

| Status | Meaning |
| --- | --- |
| `200` | Refreshed — new cookies set |
| `401` | Session expired or already used — sign in again |

## `POST /api/auth/logout`

Revokes the current refresh token and clears both cookies. No body
required.

| Status | Meaning |
| --- | --- |
| `200` | Logged out |

## `GET /api/auth/me`

Protected — requires a valid access token cookie.

| Status | Meaning |
| --- | --- |
| `200` | `{ user }` for the authenticated session |
| `401` | Not authenticated / invalid or expired access token |

## `UserResponse` shape

Every endpoint that returns a user uses this shape (password hash is never
exposed):

```json
{
  "id": "6ab3cde11cbb6d8cdcc58a4a",
  "email": "you@company.com",
  "companyName": "Acme Inc",
  "emailVerified": true
}
```

## Authentication for everything else

Every endpoint below (except `/api/demo/*`) accepts either the access cookie
set by `verify-otp` / `login`, or an API token sent as
`Authorization: Bearer plk_...` (create one under **Settings → API tokens**,
or with `POST /api/tokens`). The web app retries a request once after
`POST /api/auth/refresh` when it gets a `401`.

## `GET /api/bugs`

The demo bugs you can fix: `[{ id, title, issue, tier }]`.

## `POST /api/runs`

Starts a fix run.

| Field | Type | Meaning |
| --- | --- | --- |
| `bugId` | string | required, an id from `GET /api/bugs` |
| `engine` | `"graph"` or `"loop"` | `graph` = LangGraph agent team, `loop` = older single-agent loop |
| `replay` | boolean | re-stream a recorded real run for this bug when one exists |

**Response:** `{ runId, mode, engine, notice? }`. `mode` is the mode actually
used (`fake`, `hybrid`, `live` or `replay`); `notice` explains a fallback,
for example when no recorded run exists.

## `GET /api/runs`

Your runs, newest first: `[Run]`.

## `GET /api/runs/:id`

```json
{
  "id": "…", "userId": "…", "bugId": "paginate", "agentRunId": "…",
  "mode": "fake", "engine": "graph", "status": "completed",
  "solved": true, "bestNodeId": 5, "nodes": [],
  "usage": { "prompt_tokens": 4645, "completion_tokens": 1310 },
  "latencyMs": 5100, "prUrl": null,
  "createdAt": "…", "completedAt": "…"
}
```

`nodes` holds the node objects described below.

## `GET /api/runs/:id/events`

Server-sent events, relayed unchanged from the agent service. Each message is
`data: {"type": T, "data": {...}}` followed by a blank line. Events already
emitted are replayed first, so a client can connect late or reconnect.

| `type` | `data` |
| --- | --- |
| `run_started` | `{ run_id, bug_id, mode, engine }` |
| `guard` | `{ stage, verdict, reasons, latency_ms }` with `stage` one of `input`, `output` (the policy gate result is on each `node.policy`) and `verdict` one of `pass`, `block` |
| `triage` | `{ cause, strategies }` |
| `round` | `{ depth }` |
| `node` | `{ id, parent, depth, idea, strategy, code, output, passed, total, score, model, latency_ms, tokens, policy: { ok, reasons }, security: { ok, new_findings } }` |
| `critic` | `{ node_id, lesson }` |
| `done` | `{ solved, best, usage: { prompt_tokens, completion_tokens }, latency_ms, time_to_first_node_ms }`; `best` is the best node object (or `null`) |
| `pr` | `{ url }` |
| `error` | `{ stage, message }` |
| `end` | always last; close the stream |

Node `0` is the original buggy code (`parent: null`, `depth: 0`). Runs of the
`loop` engine send no `guard`, `triage` or `critic` events, and their nodes may
lack `strategy`, `latency_ms`, `tokens`, `policy` and `security`.

## `POST /api/runs/:id/pr`

Opens a GitHub pull request with the winning fix and its test output and
returns `{ url }`; `400` when the run is not solved. Agents never merge or
push to main: a human reviews and merges the pull request.

## GitHub (GitHub App)

| Method | Path | Result |
| --- | --- | --- |
| `GET` | `/api/github/status` | `{ connected, mode: "app" or "demo" or null, login, avatarUrl, installationId, appConfigured, repoCount }` |
| `GET` | `/api/github/connect` | `{ url }`, the GitHub App install URL; `503` when the app is not configured |
| `POST` | `/api/github/demo` | connects the offline demo account (bundled demo repositories, simulated PRs and merges) |
| `DELETE` | `/api/github` | disconnects |
| `GET` | `/api/github/repos?q=` | `[{ fullName, private, defaultBranch, description, language, updatedAt }]` for the repositories granted to the app |
| `GET` | `/api/github/repos/:owner/:repo/branches` | `[{ name, default }]` |

## Tasks and repo runs

`POST /api/tasks` with `{ repo, branch, task, autoPr }` returns `{ runId }`
(`409` when GitHub is not connected, `429` after 10 tasks per hour). The run
is then read like any other run (`GET /api/runs/:id`, `/events`). Run objects
carry `kind` (`bug` or `repo`), `repo`, `branch`, `task`, `source`, `prNumber`,
`prBranch`, `filesChanged` (a number), `bestPassed`/`bestTotal`, `merged`, `cost`, `safety` (`{guard:{input,output}, policy:{best_ok,blocked,candidates,reasons}, security:{best_ok,blocked,scanned,scanner}}`), `slackSent` (true once the completion message went to Slack), `traceId`.

Repo runs add these events before `guard`, `triage`, `round`, `node`, `critic`
and `done`:

| `type` | `data` |
| --- | --- |
| `repo` | `{ full_name, branch, files, language, test_command, truncated }` |
| `locate` | `{ files: [{ path, reason }] }` |
| `repro` | `{ path, test_name, failed_on_original, output_tail }` |
| `pr` | `{ url, branch, number, fake, updated? }`, after `done` |

`node` events may also carry `files` (path to content) and `diff` (unified diff).

## Pull request, merge and follow-up

| Method | Path | Result |
| --- | --- | --- |
| `GET` | `/api/runs/:id/pr` | `{ url, number, state, mergeable, checks: { state, failing }, mergeAllowed, reason }` |
| `POST` | `/api/runs/:id/merge` | body `{ method? }`. Merges as the signed-in user; `409 { error }` unless the PR is open, mergeable and checks passed (no CI is allowed with a `warning`). Only a human action. |
| `POST` | `/api/runs/:id/followup` | body `{ message }`, returns `{ runId }`; pushes one new commit to the same branch |

## Slack and notifications

| Method | Path | Result |
| --- | --- | --- |
| `GET` / `PUT` / `DELETE` | `/api/settings/slack` | `{ configured, webhookUrlMasked }`; `PUT` body `{ webhookUrl }` must start with `https://hooks.slack.com/` |
| `POST` | `/api/settings/slack/test` | sends a test message |
| `POST` | `/api/slack/link-code` | `{ code, expiresAt }`, for `/patchloop link CODE` in Slack |
| `GET` | `/api/notifications` | `{notifications:[{id,kind,title,body,runId,read,createdAt}], unread}`; `POST /api/notifications/:id/read` marks one read. Kinds: `pr_opened`, `pr_updated`, `merged`, `failed` |

Slack commands and GitHub issue triggers need the Slack app and the GitHub App
to be set up by the operator of the server.

## API tokens

| Method | Path | Result |
| --- | --- | --- |
| `POST` | `/api/tokens` | body `{ name }`, returns `{ token }`. The plaintext token (prefix `plk_`) is shown once. |
| `GET` | `/api/tokens` | `[{ id, name, prefix, createdAt, lastUsedAt }]` |
| `DELETE` | `/api/tokens/:id` | revokes the token |

## Guest demo (no login)

| Method | Path | Result |
| --- | --- | --- |
| `GET` | `/api/demo/bugs` | `[{ id, title, issue, tier }]` |
| `POST` | `/api/demo/runs` | body `{ bugId }`, returns `{ runId, mode, engine }`. Replay or fake mode only; 3 runs per hour per IP, then `429` with `{ error }`. |
| `GET` | `/api/demo/runs/:id/events` | the same event stream as above |

This is what the public [/try](/try) page uses.

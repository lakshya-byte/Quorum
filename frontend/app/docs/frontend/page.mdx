# Frontend

Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS v4. A small design
system lives in `app/_ui/`, design tokens in `app/globals.css`. Everything runs
without the real backend through `mocks/server.mjs`.

## Layout of the code

```
app/
  layout.tsx, globals.css          # root layout, tokens, focus + motion rules
  _ui/                             # design system: Button, Card, Badge/StatusChip, Field (Input,
                                   #   Textarea), Stepper, Tabs, Toast, EmptyState, Skeleton, Icon, Logo
  _lib/                            # api.ts (typed API layer), auth.tsx, runState.ts (event reducer),
                                   #   useRunStream.ts (SSE + reconnect), diff.ts, unified.ts (diff parser)
  _components/
    shell/                         # AppShell (sidebar, topbar, mobile drawer), NotificationsBell, CommandPalette
    run/                           # RunView, Pipeline, AttemptTree, NodeCard, NodePanel, DiffViewer, PrCard

  (marketing)/                     # "/" landing page
  (auth)/                          # /signin, /signup (+ 6-digit code step)
  (app)/                           # AuthProvider + AppShell
    dashboard/  new/  runs/[id]/  integrations/  settings/tokens/  try/
  docs/                            # this documentation (MDX)

mocks/server.mjs, mocks/repos.mjs  # dependency-free mock backend and demo repositories
e2e/flow.cjs                       # Playwright walk through the whole product flow
```

## Design system

- **One accent.** Emerald (`--primary`) for actions and success, cyan (`--secondary`) for
  "in progress", amber (`--warning`) for caution, red (`--error`) for failures. Surfaces are a
  layered dark scale (`--bg`, `--panel`, `--surface-container-*`) with 1px borders (`--border`,
  `--border-strong`).
- **Type.** Geist for UI, JetBrains Mono for code, ids and numbers. Sizes are set per component
  from a short scale (12, 13, 14, 15, 18, 26–60 px).
- **Icons** are inline SVG paths in `_ui/Icon.tsx`. Nothing is fetched at runtime.
- **Accessibility.** A global `:focus-visible` ring, labelled form controls (`Field`), a skip link,
  `aria-current` on navigation, roving-tabindex tabs, `role="alert"/"status"` for errors and toasts,
  text colours chosen for AA contrast on the dark surfaces, and `prefers-reduced-motion` support
  (all CSS animation is neutralised; the landing demo shows a static final frame).
- **Responsive.** Everything works down to 375 px with no horizontal scroll (checked by the e2e script).
  The sidebar becomes a drawer, tables become cards.
- **Theme.** Dark only. There is no light theme yet.

## Pages

| Route | Purpose |
| --- | --- |
| `/` | Landing page: promise, scripted live demo (the real `AttemptTree` and `Pipeline` fed by scripted events), seven steps, system map and agent-team diagrams (inline SVG), the four entry points, trust, FAQ |
| `/signin`, `/signup` | Email and password, then a 6-digit code |
| `/dashboard` | Onboarding checklist (GitHub, first run, Slack), stats, run history with source, status, tests, cost, speed, safety, PR and trace id |

Press <kbd>Ctrl</kbd>/<kbd>Cmd</kbd> + <kbd>K</kbd> in the app for the command palette (pages, repositories, recent runs).

### How a repo run renders

`useRunStream` opens an `EventSource` (with credentials, reconnect with backoff) and feeds every
message to the pure reducer in `_lib/runState.ts`. Besides the older `guard`, `triage`, `round`,
`node`, `critic`, `done` and `error` events it understands `repo`, `locate`, `repro`, `pr`
(including `updated: true` for follow-ups) and an optional `slack` event. Unknown events are
ignored. `pipelineStages(state)` turns the state into the eight stage chips. A finished run is
rendered from `GET /api/runs/:id` without streaming.

Nodes may carry `files` (path → content) and `diff` (unified diff). `DiffViewer` parses the diff
per file (`_lib/unified.ts`); older single-file runs fall back to the LCS line diff in `_lib/diff.ts`.

### Merge is a human action

The PR card calls `GET /api/runs/:id/pr` for state and checks, and `POST /api/runs/:id/merge` only
after you press **Merge pull request** and confirm. The button is disabled with the server's reason
unless `mergeAllowed`. With no CI configured, a warning is shown. **Ask for changes** posts to
`POST /api/runs/:id/followup`, which pushes one new commit to the same branch.

## Mock backend

`npm run mock` starts `mocks/server.mjs` on :8080 (see [Getting started](/docs/getting-started)).
It implements auth, demo bugs, runs and SSE, the GitHub App endpoints (demo account; set
`MOCK_GITHUB_APP=1` to simulate the install redirect), three demo repositories
(`demo/inventory-api`, `demo/billing-utils`, `demo/text-tools`), tasks, repo run streams with every
event type and a fake PR, PR status with checks, a fake merge, follow-ups, Slack settings and link
codes, notifications and API tokens. It uses the same cookie contract as the Go backend.

## End-to-end script

```bash
cd frontend
npm run build && npx next start -p 3000      # terminal 1
node e2e/flow.cjs [screenshot-dir]            # terminal 2: starts the mock, drives Chromium
```

The script signs up, connects GitHub (App install, then demo), saves a Slack webhook, runs a fix
through `/new`, watches it live, asks for changes, merges, runs a repo without CI, and then repeats
key pages at 375 px, failing on any page error or horizontal overflow.

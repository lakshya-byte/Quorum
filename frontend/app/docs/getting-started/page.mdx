# Getting started

PatchLoop is three services in one monorepo:

| Service | Folder | Port | Who talks to it |
| --- | --- | --- | --- |
| Frontend (Next.js) | `frontend/` | `3000` | the browser |
| Backend API (Go + Gin + MongoDB) | `backend/` | `8080` | the frontend and the CLI |
| Agent service (Python + FastAPI + LangGraph) | `agent/` | `8001` | the backend only (internal) |

The browser and the CLI only ever call the backend. The backend starts runs on
the agent service, relays its event stream unchanged, stores results in MongoDB
and opens pull requests. The agent service is never exposed to the browser.

## Prerequisites

- Node.js 20+ and npm
- Go 1.22+
- Python 3.11+
- A running MongoDB instance (local or Docker)
- Optional, for real runs: a Nebius API key (Token Factory for Nemotron models,
  Nebius Sandboxes for isolated test runs), a GitHub token for pull requests,
  a Resend key for OTP emails

## 1. Agent service (port 8001, internal)

```bash
cd agent
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # AGENT_SHARED_SECRET, NEBIUS_*, MODEL_*, GITHUB_*
uvicorn app.main:app --port 8001
```

Without Nebius credentials runs use `fake` mode: scripted fixes, tested in a
local subprocess, no tokens spent. See `agent/README.md` for the modes.

## 2. Backend (port 8080)

```bash
cd backend
cp .env.example .env          # JWT secrets, Mongo URI, FRONTEND_ORIGIN, agent URL and secret
go run ./cmd/api
```

Quick local Mongo via Docker:

```bash
docker run -d --name patchloop-mongo -p 27017:27017 mongo:7
```

`FRONTEND_ORIGIN` must match where the frontend runs (default
`http://localhost:3000`), because the frontend calls the API with cookies.

```bash
curl http://localhost:8080/health
# {"status":"ok"}
```

## 3. Frontend (port 3000)

```bash
cd frontend
npm ci
npm run dev
```

The API base URL comes from `NEXT_PUBLIC_API_URL` (default
`http://localhost:8080`). Routes:

- `/` — landing page
- `/try` — public live demo, no account needed
- `/signup`, `/signin` — email + password, verified with a 6-digit code
- `/dashboard` — your runs and the "New fix" panel
- `/runs/[id]` — the live tree of attempts for one run
- `/settings/tokens` — API tokens for the CLI
- `/docs` — this documentation

## Frontend without the backend: the mock

`frontend/mocks/server.mjs` is a dependency-free mock of the backend API: auth
with cookies and Bearer tokens, bugs, runs, tokens, the guest demo, the GitHub
App endpoints with a demo account (set `MOCK_GITHUB_APP=1` to simulate the
install redirect), three demo repositories (`demo/inventory-api`,
`demo/billing-utils`, `demo/text-tools`), tasks, repo runs with a fake pull
request, checks and a fake merge, follow-ups, Slack settings and link codes,
notifications, and scripted event streams with every event type (guards, triage, parallel nodes, a
policy-blocked node, a security-flagged node, critic lessons, a winner, an
unsolved run and a run blocked by the input guard). Any OTP code `123456` works.

```bash
cd frontend
npm run mock                      # MOCK_PORT=8080 by default
npm run dev                       # NEXT_PUBLIC_API_URL defaults to http://localhost:8080
```

Use other ports if the real backend is already on 8080:

```bash
MOCK_PORT=18090 FRONTEND_ORIGIN=http://localhost:13000 npm run mock
NEXT_PUBLIC_API_URL=http://localhost:18090 npx next dev -p 13000
```

Mock knobs: `MOCK_SPEED` (timing multiplier), `MOCK_DEMO_LIMIT` (guest runs per
hour, default 3), `MOCK_ACCESS_TTL` (access cookie lifetime in seconds, to test
refresh), `MOCK_GITHUB_APP=1` (GitHub App install flow), `MOCK_DROP_ONCE=1` (cuts each stream once, to test reconnects).
